1. Présentation de la séance

Problématique : comment un utilisateur peut-il identifier une tentative de phishing et comment une organisation peut-elle réduire les risques associés ?

Le phishing (hameçonnage) vise à inciter une personne à cliquer sur un lien, ouvrir une pièce jointe, communiquer un mot de passe ou des informations confidentielles. L’attaquant peut se faire passer pour une banque, un fournisseur, un service informatique, un collègue ou une administration.

Objectifs pédagogiques

  • Comprendre le fonctionnement d’une simulation de phishing.
  • Identifier les indices d’un e-mail suspect.
  • Utiliser des outils d’analyse dans un laboratoire isolé.
  • Parcourir les six options du menu de SET et expliquer le piège pédagogique associé.
  • Expliquer le rôle des filtres anti-phishing et anti-spam.
  • Expliquer pourquoi la MFA renforce la sécurité.
  • Produire un support de sensibilisation et des captures commentées.

3. Comprendre le scénario de phishing

1 — Réception
E-mail annonçant une suspension imminente du compte.
2 — Manipulation
Le message pousse à cliquer rapidement sur un lien.
3 — Risque
Le lien mène à une page frauduleuse qui récupère les identifiants.
4 — Protection
Vérifier l’expéditeur, signaler, ne pas cliquer.

Exemple de message suspect (fictif, à ne pas envoyer)

Objet : URGENT — Votre compte sera suspendu
Bonjour,
Une activité inhabituelle a été détectée sur votre compte. Pour éviter sa suspension, veuillez vérifier vos informations immédiatement.
Action demandée : cliquer sur un lien et saisir son mot de passe.
Cordialement, Service informatique

Signaux d’alerte

  • Urgence artificielle et menace de suspension.
  • Absence de contexte précis.
  • Demande de mot de passe par un lien reçu par e-mail.
  • Identité de l’expéditeur à vérifier.
Un e-mail malveillant peut être bien rédigé et sans faute d’orthographe.

ÉlémentRôle

Messages de test fictifsFichiers .eml, captures, pages de démonstration locales
Règles de sécurité
  • Comptes et données exclusivement fictifs.
  • Aucun message de phishing envoyé à de vrais utilisateurs ; aucun vrai mot de passe collecté.
  • Aucune page de simulation exposée sur Internet.
  • Réseau interne virtuel ou Host-only, sans pont vers le réseau de l’établissement.
  • Instantané de la VM avant l’atelier (VMware ou VirtualBox).

Vérifier l’environnement

kali@kali:~$ cat /etc/os-release
kali@kali:~$ whoami
kali@kali:~$ ip addr
kali@kali:~$ command -v setoolkit

whoami affiche l’utilisateur connecté, ip addr les interfaces réseau, command -v setoolkit vérifie la présence de SET.

Si SET est absent, vérifier sa disponibilité dans les dépôts officiels puis l’installer dans le laboratoire :

kali@kali:~$ sudo apt update
kali@kali:~$ apt-cache policy set
kali@kali:~$ sudo apt install set

5. Découvrir le Social-Engineer Toolkit (SET)

SET est un ensemble d’outils pour étudier les risques d’ingénierie sociale et conduire des tests de sécurité autorisés. Ici, il sert à comprendre le mécanisme d’une attaque et à observer les défenses, pas à récupérer des identifiants.

kali@kali:~$ sudo setoolkit

Travail demandé

  1. Repérer le menu principal.
  2. Identifier la rubrique d’ingénierie sociale.
  3. Observer les catégories sans lancer d’attaque.
  4. Quitter proprement l’application.
Limite pédagogique : on n’active pas la collecte d’identifiants, le clonage de pages de connexion ni l’envoi de campagnes. La démonstration repose sur l’observation de l’interface et sur des messages fictifs.

Option 1 — Social-Engineering Attacks

Rubrique la plus pertinente pour comprendre la manipulation humaine ; on l’observe sans lancer de campagne.

De : Assistance informatique — identité non vérifiée
Objet : Votre compte sera suspendu dans 15 minutes
Une activité inhabituelle a été détectée. Veuillez effectuer une vérification immédiate.
[ Vérifiez votre compte immédiatement ] (bouton fictif, non cliquable)

Les quatre pièges : la peur de perdre l’accès, l’urgence (15 minutes), l’autorité du service informatique, l’action par un lien plutôt que par le portail habituel.

Bonne réaction : ne pas cliquer, vérifier par un canal connu. En classe : demander aux étudiants ce qu’ils feraient avant de révéler les pièges.

Option 2 — Penetration Testing (Fast-Track)

Un risque ne se limite pas aux e-mails : il touche aussi les services et logiciels exposés.

RAPPORT DE TEST — LABORATOIRE
Cible : MACHINE-TEST-01
Autorisation : Laboratoire pédagogique
Réseau : Réseau virtuel isolé
Services observés : Service Web de test, Service de connexion distant
Analyse : configuration, mises à jour, authentification à vérifier
Exploitation : NON EXECUTEE

Rapport de démonstration, pas la sortie réelle de Fast-Track.

Piège : croire qu’un service accessible est forcément sécurisé (vulnérabilité connue, service exposé inutilement, authentification faible, mise à jour manquante liée à une CVE).

Manipulation : présenter une fiche de vulnérabilité fictive (logiciel, version installée, correctif recommandé) et demander ce qu’il faut vérifier avant de conclure.

Option 3 — Third Party Modules

Un module inconnu présenté comme « détecteur de phishing automatique » : un nom professionnel ne suffit pas.

CONTROLE D’UN MODULE TIERS
Nom : MailGuard-Pro (fictif)
Source : Non vérifiée   Auteur : Inconnu
Code source : Non examiné   Permissions : Inconnues
Décision : NE PAS INSTALLER

Pièges : nom rassurant, permissions excessives, envoi d’informations vers un serveur extérieur, documentation convaincante mais code non sûr.

Exercice : rédiger trois vérifications préalables — provenance, examen du code, contrôle des permissions.

Option 4 — Update the Social-Engineer Toolkit 
CONTROLE DES MISES A JOUR
Outil : SET
Version locale : Version A   Version cible : Version B
Etat : Mise à jour à vérifier
Résultat : Aucune mise à jour exécutée

A et B sont des valeurs fictives. Piège : un outil ancien peut avoir des défauts connus, mais être à jour ne signifie pas être sécurisé : il faut aussi examiner configuration, permissions et dépendances.

kali@kali:~$ sudo apt update
kali@kali:~$ apt list --upgradable

Question : différence entre rechercher et installer les mises à jour ? Réponse : la première actualise les informations disponibles, la seconde modifie les logiciels installés.

Option 5 — Update SET configuration

Une erreur de configuration peut exposer un service involontairement ou provoquer une communication vers l’extérieur.

CONTROLE DE CONFIGURATION
Environnement isolé : A vérifier
Données fictives : Oui
Collecte de mots de passe : Désactivée
Communication externe : Interdite
Décision : VERIFIER AVANT UTILISATION

À vérifier : type de réseau virtuel, services en écoute, données manipulées, communications autorisées, permissions de l’outil.

kali@kali:~$ ip addr
kali@kali:~$ ss -lntup

Un service en écoute n’est pas forcément accessible depuis Internet : examiner interfaces, pare-feu, routage et règles réseau.

Question : pourquoi préférer Host-only au mode en pont ? Réponse : il limite les communications au périmètre prévu du laboratoire, sous réserve de la configuration réelle.

Piège : croire qu’un outil est sans danger parce qu’il est fourni avec Kali. Un outil légitime peut être mal utilisé : il faut comprendre ses effets et les limites de l’autorisation. Documentation : page officielle de SET.

7. Le piège central : que se passe-t-il après le clic ?

1. L’utilisateur reçoit un faux e-mail « Votre compte sera suspendu ».
2. Il clique sur un lien trompeur : le site peut imiter le portail de son organisation.
3. Il saisit ses identifiants, qui peuvent être récupérés sur un vrai site frauduleux.

Sans protection suffisante : risque d’accès non autorisé. Avec plusieurs défenses : filtrage, signalement et MFA résistante au phishing réduisent le risque.

Scénario explicatif : chaque clic ne conduit pas forcément au vol d’un compte.

8. Analyse d’e-mails suspects

ÉlémentPoints de contrôle
A. L’expéditeurComparer le nom affiché et l’adresse réelle.
B. Le lienExaminer le domaine de destination sans cliquer.
C. La pièce jointeFichiers inattendus, extensions trompeuses, demandes d’activation de macros.
D. Les en-têtesFrom, Reply-To, Return-Path, résultats SPF, DKIM et DMARC.

Examiner un fichier e-mail fictif

kali@kali:~$ mkdir -p ~/atelier-phishing
kali@kali:~$ cd ~/atelier-phishing
kali@kali:~$ nano message-suspect.eml
From: "Support informatique" <support@example.invalid>
To: etudiant@example.invalid
Subject: URGENT - Vérification du compte
MIME-Version: 1.0
Content-Type: text/plain; charset=UTF-8

Votre compte nécessite une vérification immédiate.
Ne saisissez aucune information personnelle.
Ceci est un message fictif destiné à un exercice.
kali@kali:~$ cat message-suspect.eml

L’extension .invalid évite de désigner un vrai domaine.

Questions

  • Pourquoi le mot « URGENT » mérite-t-il notre attention ?
  • Le nom « Support informatique » authentifie-t-il l’expéditeur ?
  • Que vérifier si le message contenait un lien ?
  • Pourquoi ne pas transmettre son mot de passe par un lien inattendu ?

Message réel reçu

Utiliser « Afficher l’original » ou « Afficher la source ». Un résultat SPF/DKIM/DMARC positif ne prouve pas la légitimité : un compte authentique compromis peut envoyer des messages frauduleux.

Ne pas transférer de données confidentielles à un service d’analyse public.

9. L’intérêt des filtres anti-phishing

L’utilisateur ne doit pas être le seul rempart. Le filtre analyse chaque message entrant (réputation, expéditeur, liens, pièces jointes, authentification), puis l’accepte sous surveillance ou le marque suspect (avertissement, quarantaine, blocage). Il réduit les messages frauduleux sans tout détecter.

MesureFonction
Filtre anti-spamDétecte les messages indésirables et suspects.
Anti-phishingRepère fraude et usurpation.
SPFIndique quels serveurs peuvent envoyer pour un domaine.
DKIMVérifie une signature cryptographique du message.
DMARCPolitique de traitement et de signalement des échecs d’authentification.
Protection liens et pièces jointesAnalyse destinations et fichiers suspects.
SignalementPermet d’alerter le service informatique.

Exercice : identifier ces protections dans une messagerie de démonstration ou la documentation de Microsoft 365 ou Google Workspace, sans modifier un vrai domaine.

10. Pourquoi activer la MFA ?

La MFA exige plusieurs preuves d’identité : ce que l’on connaît (mot de passe), ce que l’on possède (clé de sécurité, appareil), ce que l’on est (biométrie).

Sans MFAAvec MFA
Un mot de passe récupéré peut suffire à se connecter.Le mot de passe seul ne suffit normalement plus : l’attaquant doit aussi contourner le second facteur.
La MFA ne supprime pas tous les risques : une victime peut être manipulée pour approuver une demande frauduleuse.
Bonne pratique : privilégier les clés FIDO2 ou passkeys, et ne jamais approuver une demande d’authentification inattendue.

11. Mise en situation : analyser trois e-mails

10 minutes, seul ou en binôme. Pour chaque message : légitime probable / phishing probable / suspect à vérifier / vérifier par un canal indépendant.

MessageContenu
A — BanqueVotre compte sera bloqué dans 10 minutes. Cliquez sur le lien et confirmez votre mot de passe.
B — CollègueVoici le document évoqué. (Pièce jointe inattendue.)
C — Service informatiqueVotre mot de passe expire bientôt. Message bien rédigé, nom affiché correct.
Éléments de correction (formateur)
  • A — Phishing probable : urgence artificielle, menace de blocage, mot de passe via un lien. Se connecter par le site ou l’application officielle.
  • B — Suspect : pièce jointe inattendue, message vague. Vérifier par un canal indépendant avant ouverture.
  • C — Suspect : bonne rédaction et nom affiché ne prouvent rien. Vérifier l’adresse réelle, passer par le portail officiel.

15. Conclusion à retenir

Le phishing exploite autant les comportements humains que les faiblesses techniques. Une organisation combine sensibilisation, filtres de messagerie, MFA, mises à jour et procédure claire de signalement.

SET permet d’étudier les mécanismes d’ingénierie sociale ; ce sont la vigilance humaine, la configuration sécurisée, le filtrage et l’authentification résistante au phishing qui réduisent le risque.

En cas de doute : ne pas cliquer, ne pas communiquer ses identifiants, vérifier par un canal indépendant.
